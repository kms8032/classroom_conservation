- **v2** (`classroom_conservation/v2/`): https://github.com/kms8032/classroom_conservation
  - v1을 고쳐 쓰지 않고 **새로 작성**한다. ...
  - `collect/auto_dataset_collect.py`는 학습용 사진 수집 스크립트로, v2 코드와 분리해서 유지한다.

### 코드 작성 규칙

- **1학년이 읽고 따라갈 수 있는 코드**를 우선한다. 짧고 영리한 코드보다 명확한 코드.
- 주석과 docstring은 **한국어**로, "무엇을"보다 **"왜"** 를 적는다.
- 파일 하나에 역할 하나. 파일·클래스 이름만 보고 역할을 알 수 있게 한다.
- 좌석처럼 상태를 갖는 대상은 클래스로 표현한다 (예: `Seat` 클래스에 상태와 타이머).
- 카메라 계정·비밀번호·IP는 **반드시 저장소 루트의 `.env`** 로 관리하고 커밋하지 않는다. v2 코드는 루트 `.env`를 읽는다 (`v2/`에 따로 만들지 않음). ...
- RTSP는 TCP로 고정한다: `import cv2` 전에 `os.environ["OPENCV_FFMPEG_CAPTURE_OPTIONS"] = "rtsp_transport;tcp"`
- 비밀번호의 특수문자는 `urllib.parse.quote(pw, safe="")`로 인코딩한다.
- 데이터베이스는 쓰지 않고 **모든 데이터를 JSON**으로 관리한다.

## 핵심 설계 (확정)

### 1. 판단 방식: 순간 캡처 → 실시간

RTSP를 **상시 연결**하고 카메라별 스레드로 **최신 프레임만 유지**한다. YOLO를 짧은 간격으로 반복 실행한다.

### 2. 좌석 점유 (일반 카메라)

- YOLO-pose로 사람을 탐지하고, **bbox 중심점이 좌석 ROI(다각형) 안에 있으면 "감지"**
- **자세(앉음/서 있음)는 판단하지 않는다.** 의자·책상·사람에 가려서 판단이 어렵기 때문
- 두 카메라에 겹쳐 보이는 좌석은 **어느 한쪽이라도 감지하면 감지**
- 좌석 상태는 시간 조건으로 바뀐다:

```
[비어 있음] ──(ROI 안에 5초 이상 연속 감지)──▶ [점유]
     ▲                                          │
     │                                     (감지 끊김)
     │                                          ▼
     └──────(1분 동안 계속 감지 안 됨)──── [확인 중]
                                                │
               [점유] ◀──(1분 안에 다시 감지)───┘
```

- 진입 대기 5초 동안은 화면에 **비어 있음** 그대로 표시 (지나가는 사람을 거르기 위함)
- 떠난 뒤 1분 동안은 **확인 중**으로 표시 (가려져서 잠깐 안 보이는 경우를 거르기 위함)
- 확인 중에 다시 감지되면 5초를 기다리지 않고 바로 점유로 복귀

### 3. 교탁·복도 인원 (301호 광각 cam5)

- 광각 이미지를 **3분할**해서 탐지 (먼 곳의 작은 사람 탐지율을 높이기 위함)
  - 조각끼리 조금씩 겹치게 자르고, 결과를 원본 좌표로 되돌린 뒤 **NMS로 중복 박스 제거**
- 광각 이미지 위에 **교탁·복도 다각형 ROI**를 지정하고, 중심점이 그 안에 있는 사람만 센다
- YOLO는 전체 이미지(사각형)에서 탐지하고, 다각형 판단은 탐지 후 `cv2.pointPolygonTest`로 한다 (마스킹 방식은 경계의 사람이 잘려서 쓰지 않음)
- 프레임마다 값이 흔들리므로 **최근 N개 결과의 중앙값**을 표시

### 4. 총 인원 계산

카메라마다 담당 구역을 나눠 **중복 세기를 피한다.**

```
301호 총 인원 = 점유 좌석 수 + 확인 중 좌석 수 + 교탁·복도 인원 수
304호 총 인원 = 점유 좌석 수 + 확인 중 좌석 수
```

- 확인 중 좌석은 사람이 아직 교실 안에 있을 수 있어 **인원에 포함**
- 알려진 오차: 좌석을 떠나 교탁·복도로 가면 최대 1분간 두 번 세어짐. 처음에는 그대로 두고, 실제 데이터에서 자주 보이면 보정 규칙 추가

### 5. 트래킹은 쓰지 않는다

판단 기준이 "사람"이 아니라 "구역(좌석·교탁·복도)"이라 사람별 ID가 필요 없다. 트래킹은 높은 FPS가 필요하고, 강의실은 가림이 많아 ID 전환 문제가 잦다. 실제 데이터에서 오판(예: 여러 사람이 연달아 같은 ROI를 지나가 점유로 판단)이 자주 보이면 그때 Ultralytics `model.track()`(ByteTrack)으로 추가한다.

### 6. VLM (Ollama, 2~4B급)

- **강의실 상태 판단만** 담당: 수업 중 / 빈 강의실 / 개인 자습
- 좌석 판정에는 관여하지 않는다
- 느리므로 YOLO와 별도로 **몇 분 간격**으로 실행

### 7. 관리자 화면

- **카메라 영상은 띄우지 않는다** (개인정보 부담)
- 좌석 점유: 강의실 **배치도 위에 좌석 상태를 색으로** 표시 (비어 있음 / 점유 / 확인 중)
- 인원: 숫자로 표시
- 갱신: 처음에는 웹이 몇 초마다 JSON을 가져오는 **폴링** 방식 (나중에 WebSocket 고려)

### 8. 조명 판정

픽셀 밝기 방식으로 결정 (301호·304호 평균 정확도 99% 이상). 강의실 열림/닫힘 판단에 사용 예정.

## 전체 처리 흐름

```
RTSP 상시 연결 (카메라별 스레드, 최신 프레임 유지)
  ├─ YOLO 짧은 간격 반복
  │    ├─ 일반 cam → 중심점 ROI 판단 → Seat 상태 갱신(타이머) → 좌석 상태
  │    └─ 광각 cam5 → 3분할 탐지 → NMS → 교탁·복도 다각형 판단 → 중앙값 → 인원 수
  └─ VLM 몇 분 간격 → 강의실 상태
        ↓
  JSON (실시간 상태 + 1분 단위 요약 로그)
        ↓
  관리자 웹 (폴링으로 배치도·숫자 갱신)
```

## 데이터

| 종류                 | 내용                                                      | 비고                         |
| -------------------- | --------------------------------------------------------- | ---------------------------- |
| 좌석 정의 (고정)     | 좌석 번호, 배치도상 위치(x, y, w, h), 카메라별 ROI 다각형 | v1에서 옮겨옴                |
| 교탁·복도 ROI (고정) | 광각 이미지 기준 다각형                                   | 새로 지정                    |
| 좌석 상태 (실시간)   | 좌석 번호, 현재 상태, 마지막 감지 시각                    | 매 갱신 덮어쓰기             |
| 요약 로그            | 1분 단위 점유 좌석·인원                                   | 매초 결과를 다 저장하지 않음 |

- 수집한 강의실 사진은 외장 SSD에 저장 (NAS 사용 안 함)
- 좌석은 지정석이라 책·인형 등 개인 물건이 상시 놓여 있음 (물건만으로 점유 판단하지 않는다)

## v1에서 참고할 것

v1 경로는 `HyoChan1117/person-count` 기준.

| v1 위치                                                                  | 내용                                                      | v2에서                                                      |
| ------------------------------------------------------------------------ | --------------------------------------------------------- | ----------------------------------------------------------- |
| `backend/data/classrooms.json` → `seat_lines`                            | 301호 좌석별 4점 다각형 ROI (CCTV 1~4, 30석)              | 좌석 ROI 데이터로 사용 (RTSP 주소·비밀번호는 옮기지 말 것)  |
| `backend/data/map_data/1.json`                                           | 301호 배치도 (`type: "desk"`, `label`=좌석 번호, x/y/w/h) | 관리자 화면 배치도                                          |
| `backend/app/services/frame_capture.py` → `_RTSPGrabber`                 | RTSP 수신·재연결 스레드                                   | 참고해서 재작성. **유휴 종료(`_IDLE_TIMEOUT`) 로직은 제거** |
| `backend/app/services/vision_llm_detection.py` → `_is_in_seat_band()`    | 점이 다각형 안인지 판단                                   | 좌석·교탁 판단 공통 함수로 재작성                           |
| `backend/app/services/vision_llm_detection.py` → `_run_seat_occupancy()` | ROI + 앉음 판단                                           | **앉음 조건(`sitting_flags`) 제거**하고 참고                |
| `backend/app/services/live_stream.py` → `_LiveWorker`                    | 카메라별 상시 추론 워커                                   | 구조 참고. 출력을 JPEG → 탐지 결과로 변경                   |

주의: v1은 모든 카메라가 하나의 `infer_lock`을 기다리는 구조다. v2에서는 여러 카메라 프레임을 **묶어서(batch) 추론**하는 방식을 우선 고려한다.

v1에 없는 것: 304호 좌석 매핑, 광각 3분할 탐지 코드.

## 미정 (구현 후 결정)

- **YOLO 추론 간격**: 5초 진입 조건을 안정적으로 판단할 수 있는 간격을 만들어보고 결정 (0.5초 정도가 후보). 한 번 놓친 감지를 허용할지도 함께 결정
- **중심점 기준**: bbox 중심 vs 엉덩이 키포인트 중간점 — 이전 데이터 지표에서 더 잘 나온 방식으로 선택
- **PTZ 역할**: 광각이 교탁 정반대(뒤쪽)에 있어 교탁 쪽 탐지가 약할 수 있음. 교탁 보조용 여부 판단
- **웹 프레임워크**: 미정

## 구현 순서

1. RTSP 상시 연결 (카메라별 스레드, 최신 프레임 유지)
2. 좌석 점유: YOLO-pose → 중심점 ROI 판단 → Seat 상태 타이머
3. 교탁·복도 카운트 (301호): 3분할 탐지 → NMS → 다각형 판단
4. 총 인원 계산 + JSON 출력
5. 관리자 웹: 배치도 + 인원 숫자 (폴링)
6. VLM 강의실 상태 판단 (별도 주기)

2번 이후 추론 간격, 3번 이후 PTZ 역할을 결정한다.
